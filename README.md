# NusaCBT

NusaCBT adalah proyek aplikasi ujian berbasis web untuk sekolah, dirancang berjalan pada server lokal dan diakses melalui jaringan sekolah tanpa koneksi internet saat ujian.

> **Status: dalam pengembangan, belum untuk ujian sungguhan atau data asli.** Login, tahun ajaran dan perpindahan siswa, kartu peserta A4, bank soal, jadwal, token, pengerjaan, izin mengulang, nilai dasar, nilai akhir, serta rekap hasil (matriks) dan unduhan Excel tersedia untuk diuji dengan data fiktif. **Ekspor soal dan backup aplikasi belum tersedia.** Word 2013, dokumen asli, Windows dan kapasitas LAN belum diuji langsung.

## Cakupan proyek

- Tujuh menu admin: Dashboard, Data Modul, Data Peserta, Data Tes, Laporan, Tool, dan Pengaturan.
- Ujian pilihan ganda dengan token, timer berbasis server, penyimpanan jawaban, snapshot, nilai per pengerjaan, izin mengulang, dan nilai akhir per tes/peserta dapat diuji. Visibilitas nilai tetap dikendalikan per kategori.
- Tahun ajaran sebagai induk periode dan roster siswa, perpindahan antar-tahun dengan pratinjau, login peserta per periode manual, monitoring terfilter dengan ekspor Excel, dan rekap matriks (siswa × tes).
- Next.js, PostgreSQL, dan komponen shadcn/ui dengan tema terang dan gelap.
- Target pengujian awal: 30 peserta bersamaan di server dan jaringan sekolah. Kapasitas dan operasi LAN tanpa internet belum teruji.

Lihat [spesifikasi kebutuhan awal](docs/kebutuhan-awal.md) untuk rincian dan keputusan yang masih terbuka.

## Penyiapan pratinjau

Persyaratan: Node.js 20.18.1 atau lebih baru dan npm; **Node.js 26 LTS disarankan**. Dependensi `cn` yang terkunci menyatakan Node.js minimal 22: npm pada Node 20 dapat memperingatkan, atau menolak instalasi bila `engine-strict` diaktifkan. PostgreSQL harus sudah berjalan. Lihat [panduan PostgreSQL dan akun admin](docs/penyiapan-database.md) untuk langkah Windows, file `.env.local`, migrasi, dan pembuatan akun.

Sebelum menjalankan migrasi pada database yang sudah ada, pastikan target dan backup database yang sesuai, serta cadangan kunci sandi peserta dan token yang cocok. Perintah migrasi menerapkan **semua migrasi yang belum tercatat**, bukan hanya `024`; tiap file memiliki transaksi sendiri. **Migrasi `024` menambah tahun ajaran sebagai induk periode dan roster siswa per tahun ajaran. Periode lama tidak otomatis dipetakan ke tahun mana pun: setelah upgrade, login peserta dinonaktifkan dan semua sesi berakhir sampai admin memetakan periode lama ke tahun ajaran dan mengaktifkan periode login secara manual. Akun, sandi, penempatan, jadwal, pengerjaan dan nilai tidak dihapus; jangan menebak pemetaan tahun.** Hentikan semua proses aplikasi lama selama pemeliharaan. Jangan menjalankan kode sebelum `024` pada database yang sudah bermigrasi. Kembalikan hanya dengan prosedur rollback dan backup database/kunci yang cocok; perubahan setelah backup bisa hilang. **Migrasi `023` menambah pengaturan, status dan audit nilai akhir tanpa menetapkan nilai lama secara otomatis; metode awal tiap tes adalah tertinggi dan izin yang ada tidak otomatis dicabut.** Jangan menjalankan kode sebelum `023` pada database yang sudah bermigrasi: kode lama tidak memeriksa penutupan nilai akhir dan dapat mengizinkan pengerjaan baru. **Migrasi `022` mengganti batas satu pengerjaan dengan batas satu pengerjaan aktif dan menambah tabel izin serta pagar tindakan.** Data pengerjaan, jawaban, nilai, snapshot, dan kebijakan lama tidak dihapus atau otomatis diulang. Hentikan seluruh aplikasi lama sebelum migrasi dan jangan menjalankannya lagi pada skema `022`: kode lama tidak kompatibel dengan beberapa pengerjaan. Rencanakan rollback menggunakan backup database dan kunci yang telah diuji bersama versi aplikasi lama; pemulihan backup akan menghilangkan perubahan sesudah waktu backup dan tidak boleh dilakukan sembarangan. **Migrasi `021` membuka secara default nilai yang selesai pada ketiga kategori, termasuk nilai lama yang dahulu tersembunyi oleh `020`.** Hentikan aplikasi lama, cadangkan dan verifikasi pemulihan, lalu rencanakan masa pemeliharaan: bila nilai tidak boleh langsung dibuka, batasi akses peserta sampai admin menyembunyikan kategori yang diperlukan di Pengaturan Pengerjaan. Tabel kebijakan per tes `020` disimpan sebagai arsip, tetapi tidak lagi digunakan oleh aplikasi baru; jawaban, nilai dan sesi tidak diubah. Pengembalian ke aplikasi lama dapat memakai lagi kebijakan per tes yang berbeda, sehingga rollback harus direncanakan bersama cadangan dan versi aplikasi. Migrasi `020` awalnya menambahkan pengaturan per tes dengan default tersembunyi. Migrasi `019` menambah tanda ragu dan pengaturan global pengumpulan, awalnya 5 menit terakhir; jawaban dan nilai lama tidak diubah. Migrasi `018` menambah tabel snapshot, pengerjaan, dan pembatas token tanpa membuat pengerjaan atau nilai secara otomatis. Migrasi `017` membuat tabel kelompok dan pelaksanaan tanpa menghapus atau otomatis merilis tes lama. **Setelah upgrade, jadwal rancangan lama tidak lagi terlihat oleh peserta sampai pelaksanaan diatur dan dirilis.** Migrasi `016` memperluas audit buka kunci; migrasi `015` yang baru diterapkan mula-mula belum memilih periode login. Jangan menebak status database atau mengganti kunci yang ada.

Ringkasan setelah database dan `.env.local` disiapkan:

```bash
npm ci
npm run db:migrate
npm run admin:create -- adminsekolah
npm run dev
```

Buka `http://localhost:3000` di komputer yang menjalankan aplikasi. Kata sandi admin dimasukkan secara tersembunyi di terminal, tidak di argumen perintah. Tidak ada akun atau kata sandi bawaan. Akun pertama saja dapat dibuat dengan perintah ini; pengaturan pengguna dan reset admin belum tersedia.

Jika database dan admin sudah disiapkan pada versi sebelumnya, pertahankan `.env.local` dan akun admin yang ada, lalu jalankan `npm ci` bila dependensi berubah dan `npm run db:migrate`; jangan membuat ulang database atau admin. Setelah masuk, buka **Data Peserta → Tahun Ajaran**: buat tahun ajaran, aktifkan, dan petakan periode lama ke tahunnya secara eksplisit di **Data Peserta → Periode Ujian**. **Periode lama tidak otomatis masuk ke tahun mana pun.** Setelah pemetaan, aktifkan periode login yang sesuai secara manual di **Data Peserta → Periode Ujian**; login peserta tetap dipilih satu periode oleh admin dan tidak berubah otomatis berdasarkan tanggal. Periode baru wajib dipilih tahun ajarannya saat dibuat.

### Topik dan mata pelajaran

Buka **Data Modul → Topik / Mata Pelajaran**. Admin dapat menambah, mencari, mengubah, dan menghapus kategori dengan konfirmasi. Ini **satu daftar fleksibel lintas periode**, bukan hierarki: `Matematika` dan `Aljabar` dapat menjadi kategori yang setara. Nama wajib 1–100 karakter Unicode tanpa karakter kontrol; spasi di awal dan akhir dibersihkan, sementara spasi di tengah dipertahankan. Nama yang hanya berbeda kapitalisasi ditolak berdasarkan `lower` dan kolasi PostgreSQL; perbedaan spasi di tengah atau bentuk normalisasi Unicode tidak disatukan secara otomatis.

Jika data berubah ketika formulir terbuka, simpan atau hapus ditolak agar tidak menimpa perubahan lain; gunakan **Muat ulang daftar** lalu periksa kembali. Kategori yang masih digunakan soal tidak dapat dihapus. Soal merujuk ID kategori dengan `ON DELETE RESTRICT`; mengganti nama kategori tidak mengubah ID-nya.

### Manajemen soal manual

1. Setelah `npm ci` dan migrasi sampai `010`, buat setidaknya satu kategori di **Data Modul → Topik / Mata Pelajaran**. Buka **Manajemen Soal → Tambah soal**, pilih satu kategori, isi soal dan pilihan **A–E**, lalu tandai tepat satu jawaban benar.
2. Isi soal dan setiap pilihan wajib mengandung teks, gambar, atau keduanya. Editor pada keenam bagian mendukung tebal, miring, garis bawah, sub/superskrip, daftar, perataan, arah RTL/LTR, dan pembuatan/pengubahan tabel. Letakkan kursor pada paragraf Arab, lalu pilih **RTL**; periksa pula susunan campuran Arab, angka, dan simbol. Rumus yang didukung dapat ditampilkan, tetapi belum dapat diedit sebagai rumus. Baca langkah penempelan di bawah.
3. Isi berformat disimpan sebagai struktur tervalidasi serta salinan teks untuk pencarian, bukan HTML bebas. Teks pencarian maksimal 5.000 karakter Unicode untuk soal dan 2.000 per pilihan. Tabel maksimal 30 baris, 12 kolom, dan 250 sel per bagian. Data soal lama yang belum memiliki format tetap dapat dibaca dan diubah.
4. Setiap bagian dapat memiliki maksimal **satu gambar**: satu untuk soal dan satu untuk masing-masing pilihan; **PNG/JPEG statis**, maksimal **1 MiB per gambar sebelum dan sesudah diproses**, maksimal 4.000 piksel tiap sisi dan 8 megapiksel. SVG, WebP, APNG, gambar rusak, atau gambar yang terlalu besar ditolak. Gambar tampil setelah teks/tabel, tidak di posisi semula. Jika hasil pemrosesan melebihi 1 MiB, perkecil/kompres gambar dan pilih ulang.
5. Klik **Simpan soal** dan tunggu pesan berhasil. File baru terlihat setelah penyimpanan; perubahan yang hanya ada di formulir belum tersimpan. Daftar dapat dicari berdasarkan teks atau difilter berdasarkan kategori; tombol **Lihat** menampilkan pilihan dan kunci untuk admin. **Ubah** mempertahankan gambar lama kecuali dipilih pengganti atau dicentang untuk dihapus. Pilih salah satu, bukan penggantian dan penghapusan sekaligus. Hapus soal memerlukan konfirmasi dan menghapus gambar yang melekat; soal yang masih dipilih di rancangan tes tidak dapat dihapus.
6. Saat ada perubahan atau penghapusan oleh sesi lain, operasi pada formulir usang ditolak. Gunakan **Muat ulang daftar**, periksa kembali, dan isi ulang perubahan yang diperlukan. Jika hasil belum dapat dipastikan karena gangguan koneksi, periksa daftar sebelum mencoba lagi agar tidak membuat duplikat. Format tersimpan yang tidak valid diblokir agar tidak tertimpa diam-diam.

Gambar didekode dan dienkode ulang untuk membuang metadata, lalu disimpan di PostgreSQL bersama soal dalam satu transaksi; file aslinya tidak disimpan dan isi soal/gambar tidak dienkripsi oleh aplikasi. Jika ada proxy, pastikan batas body-nya mengizinkan permintaan hingga 8 MB untuk enam gambar. Pencarian dan paginasi pada tahap ini dilakukan di browser setelah semua teks soal dimuat; kinerja bank soal besar belum diuji. Semua admin yang login dapat melihat kunci dan gambar. Halaman dan gambar tidak dimaksudkan untuk akses publik; gunakan HTTPS tepercaya dan perangkat admin yang aman, serta batasi akses server/database. Log database dapat memuat isi soal saat terjadi kesalahan: batasi akses dan masa simpan log, serta hindari merekam body permintaan/respons di proxy. Backup database harus mencakup gambar ini, disimpan aman dan diuji pemulihannya. Fitur backup aplikasi belum tersedia.

### Menempel rumus dari Word

1. Di Word, pilih sebuah Equation bawaan, buka **Equation Tools / Design → Tools → Equation Options** (tombol panah kecil), dan aktifkan **Copy MathML to the clipboard as plain text**. Nama/menu dapat sedikit berbeda menurut versi Word.
2. Pilih **satu rumus lengkap saja**, salin, lalu tempel pada posisi kursor di editor soal atau pilihan. Salin teks dan tabel terpisah dari rumus; tempelan yang terdeteksi mengandung campuran rumus/gambar dan teks ditolak, bukan sebagian ditempel. Unggah gambar dengan tombol file. Jika hasil berupa teks linear, hapus dan periksa kembali pengaturan Word.
3. Periksa hasil sebelum menyimpan. Sebagian MathML dasar, seperti pecahan, akar, pangkat, subskrip, dan kurung, dapat dirender; bentuk yang tidak didukung ditolak. Font, spasi, dan tata letak dapat berbeda dari Word. Rumus hanya untuk ditampilkan, tidak diedit dengan editor rumus aplikasi.

**Batas penting:** cara ini telah diuji dengan data clipboard MathML fiktif di Chromium, bukan menyalin langsung dari Word 2013/Windows. Dukungan semua bentuk Equation dan hasil identik dengan Word belum dijamin.

### Impor soal Word (.docx)

1. Buka **Data Modul → Import Soal Word**, unduh `template-soal-nusacbt.docx`, dan hapus/ganti **keempat soal fiktif** di dalamnya. Satu file digunakan untuk satu kategori yang dipilih di aplikasi. File harus `.docx` maksimal **6 MiB** dan **100 soal**; `.doc`, `.docm`, dan PDF tidak diimpor.
2. Gunakan **satu tabel utama** dengan kolom `No`, `Jenis`, `Isi`, `Jawaban`. Untuk setiap soal, satu baris `SOAL` (kolom Jawaban kosong) diikuti **lima** baris `JAWABAN`. Isi `1` pada tepat satu jawaban benar dan `0` pada empat lainnya. Urutan baris menjadi pilihan A–E; `No` hanya penanda, bukan ID database. Gabungan vertikal pada kolom No dapat dipakai. Semua soal yang diimpor harus berada di tabel utama; teks di luar tabel tidak diimpor.
3. Editor membaca teks berformat dasar, Arab, tabel di dalam sel isi, sebagian Equation Word (pecahan dasar, akar, pangkat/subskrip, kurung, dan fungsi), serta maksimal satu gambar PNG/JPEG per soal/pilihan. Total gambar setelah diproses maksimal **16 MiB per file**, termasuk setiap pemakaian ulang gambar yang sama; jika lebih, bagi dokumen menjadi beberapa file. Tabel isi mengikuti batas di atas, tidak boleh berisi tabel atau gambar di dalamnya. Daftar otomatis Word, objek tertanam, gambar tertaut, serta Equation seperti integral, sigma, matriks dan bentuk lain yang belum didukung dapat menyebabkan **seluruh file ditolak**, bukan disimpan sebagian. Ubah bentuk/struktur tersebut atau masukkan gambar secara manual. Bentuk font, ukuran, warna, dan penempatan gambar dapat berbeda; periksa setiap halaman pratinjau.
4. Pilih file dan kategori, klik **Periksa pratinjau**, periksa soal, pilihan, kunci, tabel, gambar, dan rumus di semua halaman, lalu **Simpan hasil impor → Ya, simpan impor**. Seluruh soal disimpan dalam satu transaksi; soal lama tidak ditimpa. Pratinjau ulang sebagai operasi baru menambahkan soal yang sama lagi.
5. Jika hasil simpan belum pasti, **jangan muat ulang halaman atau ganti file/kategori**; periksa Manajemen Soal dan coba tombol simpan pada pratinjau yang sama. Percobaan ulang pada pratinjau yang sama tidak menambahkan duplikat. Pratinjau dan ID operasinya hilang setelah halaman dimuat ulang atau pilihan diganti; periksa daftar sebelum membuat pratinjau baru.

Template fiktif dan parser telah diuji secara otomatis, serta satu struktur Equation dari contoh Word publik yang lebih lama diperiksa; **dokumen asli dan Word 2013/Windows belum diuji langsung**. PDF acuan tidak membuktikan struktur internal `.docx`. Uji salinan fiktif di komputer sasaran dan bandingkan seluruh pratinjau dengan Word sebelum mempercayai hasil. Ekspor Word belum tersedia; soal dapat dipilih untuk rancangan dan pelaksanaan tes.

### Daftar Tes — rancangan admin

1. Setelah migrasi `011_exam_tests.sql`, buat sedikitnya satu periode dan, bila diperlukan, soal di bank. Buka **Data Tes → Daftar Tes → Tambah tes**. Pilih periode, isi nama, waktu mulai, zona waktu **WIB/WITA/WIT**, dan durasi bulat 1–10.080 menit. Waktu mulai ditafsirkan dalam zona yang dipilih, bukan zona browser atau server. Akhir terjadwal dihitung dari mulai + durasi. Jadwal saat ini **tidak diperiksa** agar berada dalam rentang tanggal periode; periksa sendiri sebelum menyimpan. Rentang tahun mulai: 2000–2100.
2. Cari/filter soal menurut topik, teks, pilihan, atau ID; pilih satu per satu atau **Pilih semua hasil** (maksimal 1.000 soal per tes). **Lihat** menampilkan isi, gambar, pilihan, dan kunci hanya untuk admin. Susun urutan dengan tombol naik/turun atau lepas pilihan. Tanpa acak soal, urutan rancangan adalah urutan pilihan ini. Boleh menyimpan tanpa soal sebagai rancangan yang belum lengkap.
3. Pengaturan **Acak urutan soal** dan **Acak urutan pilihan jawaban** menentukan urutan ketika peserta pertama kali mulai; urutan kemudian tetap pada pengerjaan tersebut. Klik **Simpan rancangan** dan tunggu pesan berhasil. Ubah melalui formulir; penghapusan meminta konfirmasi dan hanya melepaskan hubungan, bukan menghapus soal dari bank. Jika hasil simpan tidak pasti, muat ulang dan periksa daftar sebelum mencoba lagi agar tidak membuat tes ganda.
4. Rancangan merujuk ke **bank soal terkini**, bukan snapshot. Mengubah teks, gambar, pilihan, atau kunci di Manajemen Soal juga mengubah yang dirujuk rancangan. Soal terpilih tidak dapat dihapus dari bank sampai dilepas dari seluruh rancangan yang menggunakannya. Jika soal berubah ketika formulir tes terbuka, simpan ditolak; muat ulang dan periksa lagi. Perubahan formulir yang belum berhasil disimpan tidak aman.

Semua tes di sini masih **rancangan admin**. Peserta hanya melihat pelaksanaan yang sudah dirilis untuk dirinya; rancangan lama dan draf tidak otomatis terlihat. Saat peserta mulai, isi, gambar, opsi, kunci, dan urutannya dibekukan untuk pengerjaan itu. Perubahan bank sesudahnya tidak mengubah snapshot yang sudah dibuat, tetapi **peserta yang mulai kemudian dapat menerima versi soal berbeda**. Untuk keadilan, jangan mengubah soal bank selama pelaksanaan. Pencarian, pemilihan, dan paginasi di halaman ini masih dilakukan di browser setelah seluruh bank soal dimuat; kinerja bank besar belum diuji. Semua admin dapat melihat kunci; halaman dan gambar harus dibatasi, seperti Manajemen Soal.

### Kelompok sesi dan pelaksanaan tes — pratinjau

1. Setelah migrasi `017_exam_sessions_and_schedules.sql`, siapkan periode, kelas/penempatan aktif, serta identitas dan sandi seperti biasa. Di **Data Tes → Daftar Tes → Atur kelompok sesi**, pilih periode, tentukan 1–24 sesi dan kapasitas masing-masing (1–5.000). Maksimal 5.000 siswa dapat dimasukkan dalam satu pembagian. Kelompok dibuat sekali per periode dan dipakai kembali oleh tes reguler pada periode itu. Jika periode dihapus, kelompok kosong ikut dihapus; periode yang memiliki siswa dalam kelompok, pelaksanaan, atau data terkait lain tetap dilindungi.
2. Tambahkan satu atau beberapa kelas, centang individu lain, dan hapus centang pengecualian. **Acak pembagian** mengacak siswa baru dalam tiap kelas dan menyebarkannya menurut kapasitas; siswa yang sudah disimpan tidak diacak ulang. Jika total kapasitas tidak cukup, pembagian dibatalkan tanpa siswa tertinggal. Periksa pratinjau, pindahkan siswa secara manual bila diperlukan, lalu konfirmasi **Simpan pembagian sesi**. Anggota yang dipilih disimpan sebagai daftar siswa: penambahan/perpindahan kelas tidak otomatis menambah atau mengeluarkan anggota. Perubahan penempatan dapat mengakhiri sesi login; persyaratan kelas aktif, identitas, sandi, dan periode login tetap berlaku.
3. Pada baris rancangan di **Daftar Tes**, pilih **Pelaksanaan**. Tambahkan satu pelaksanaan **Reguler** per kelompok sesi untuk tes tersebut, isi nama, waktu mulai dan zona, lalu pilih anggota yang ikut. **Pilih semua yang tersedia** membantu memilih seluruh anggota aktif; individu boleh dikecualikan. Waktu di sini terpisah dari jadwal dasar rancangan, tetapi durasi reguler mengikuti induk. Perhatikan jumlah siswa kelompok yang belum dipilih; mereka tidak menerima jadwal. Simpan draf, periksa daftar dan konfirmasikan **Rilis**. Kapasitas kelompok membatasi jumlah reguler; ketersediaan ruangan/perangkat dan tanggal dalam rentang periode tidak diperiksa otomatis.
4. Tambahkan pelaksanaan **Susulan** pada waktu lain untuk peserta yang dipilih; jumlah soal, durasi dan aturan acak mengikuti induk. Soal/urutan antar-pelaksanaan tidak disyaratkan identik. **Remidi** secara default mengikuti soal induk; admin dapat memilih soal lain dari bank dengan jumlah minimal satu dan tidak melebihi jumlah soal induk. Durasi remidi dapat berbeda. Draf boleh belum memiliki peserta atau soal khusus, tetapi tidak dapat dirilis sampai lengkap.
5. Saat merilis, server memeriksa peserta berkelas aktif, soal, kapasitas dan bentrok dengan jadwal dirilis milik siswa yang sama, termasuk di periode lain. Waktu tepat berurutan tidak bentrok. Jika kelompok berubah saat dialog terbuka, muat ulang dan periksa kembali. **Tarik rilis** menyembunyikan jadwal pada permintaan berikutnya, tetapi **ditolak jika pengerjaan sudah ada**. Tarik semua jadwal reguler terkait sebelum memindahkan/mengeluarkan siswa dari kelompok. Draf tes dapat memerlukan pembaruan manual sesudah kelompok berubah. Tarik seluruh rilis sebelum mengubah induk, dan hapus seluruh pelaksanaan sebelum menghapus atau memindahkan periode induk.
6. Rilis jadwal saja tidak memulai pengerjaan: peserta harus berada dalam jadwal aktif dan memasukkan token yang berlaku. Jadwal hanya terlihat oleh siswa yang dipilih pada periode loginnya. Data yang sudah terlihat di perangkat tidak dapat ditarik kembali. Verifikasi daftar dan akses menggunakan data fiktif.

### Timeline jadwal tes

Di atas daftar rancangan, **Timeline tes** menampilkan tanggal sebagai baris di kolom kiri dan nama pelaksanaan pada skala jam mendatar. Pilih tanggal awal dan akhir secara inklusif (**1–7 hari**), lalu tekan **Terapkan rentang**; awalnya tujuh hari mulai hari ini dalam WIB. Pilih zona tampilan WIB/WITA/WIT untuk memproyeksikan seluruh jadwal pada skala yang sama. Awalnya jam **06:00–18:00** terlihat; geser mendatar untuk melihat seluruh **00:00–24:00**. Secara normal tiga hari pertama terlihat sekaligus dan hari berikutnya dapat digulir vertikal. Jika sangat banyak jadwal bertumpuk, tinggi area dibatasi dan sebagian hari juga perlu digulir. Panah rentang berpindah menurut panjang rentang yang dipilih; **Hari ini** kembali ke tanggal kini pada zona tampilan.

Pelaksanaan draf dan dirilis ditampilkan, termasuk yang waktunya bertumpuk; lajur terpisah mencegah kartu saling menutupi. Jadwal lintas tengah malam muncul pada setiap hari yang dilaluinya dengan tanda arah; jadwal yang berakhir tepat pukul 00:00 tidak muncul pada hari berikutnya. Garis warna di bawah kartu menunjukkan durasi sebenarnya; kartu singkat dapat dibuat lebih lebar agar terbaca. Garis merah pada hari ini menunjukkan perkiraan waktu menurut jam server saat halaman dimuat. Arahkan kursor/fokus ke kartu untuk detail lengkap, atau buka **Lihat daftar lengkap jadwal** untuk nama, waktu dan zona lengkap tanpa menggeser skala. Waktu asli beserta zona aslinya disertakan jika berbeda dari zona tampilan. **Sorot kategori** meredupkan kategori lain pada grafik, bukan menghapusnya. Rancangan hanya muncul jika belum memiliki pelaksanaan, ditandai **belum berkategori**, dan kliknya membuka editor rancangan. Klik pelaksanaan draf membuka editor draf; pelaksanaan yang dirilis membuka kartu pengelolaannya dan tetap tunduk pada aturan rilis. Tidak ada paginasi delapan baris lagi. Pengaturan rentang, zona dan editor memerlukan JavaScript; daftar lengkap awal tetap dapat dibaca tanpanya. Timeline tidak menerbitkan atau mengubah jadwal otomatis. Muat ulang halaman untuk mengambil perubahan jadwal terbaru.

Tombol tema di admin dan peserta langsung berganti terang/gelap dan mengingat pilihan, tidak lagi mengikuti sistem. Dialog panjang mempertahankan tombol tindakan di bagian bawah saat isi digulir.

### Pengerjaan peserta dan nilai dasar — pratinjau

1. Setelah migrasi terbaru, siapkan periode login, peserta, soal, pelaksanaan yang dirilis, serta kunci dan token fiktif. Pada jadwal yang **sedang berlangsung**, peserta memilih **Mulai tes** dan memasukkan token enam digit di modal pada halaman `/peserta`; nama tes ditampilkan untuk membantu pemeriksaan. Keenam kotak adalah satu input yang dapat diketik, diedit dengan keyboard, atau diisi dengan menempel kode; nol di depan penting dan karakter bukan angka diperingatkan. Tombol ditahan selama pemeriksaan agar tidak terkirim ganda; bila koneksi terputus, muat ulang jadwal untuk memeriksa apakah tes sudah dimulai. Tanpa JavaScript tersedia tautan formulir cadangan. Token khusus aktif mendahului global; jika khusus berakhir atau dicabut, global yang masih aktif berlaku kembali. Kode lama yang hanya berupa hash tidak dapat digunakan untuk mulai. Token dicek saat mulai, bukan selama pengerjaan.
2. Batas akhir adalah **mulai jadwal + durasi**, berdasarkan jam database, bukan waktu peserta masuk. Peserta terlambat hanya mendapat waktu yang tersisa; hitung mundur **Waktu** di header browser adalah tampilan lokal, keputusan tetap memakai jam database. Pastikan jam server/database benar. Header menampilkan nama, NISN, kelas dan periode dari sesi peserta. Tombol **Sebelumnya/Berikutnya** tetap di bawah; soal atau gambar yang panjang tetap dapat membutuhkan scroll. Soal, pilihan, gambar dan kunci dibekukan saat mulai; pengaturan acak diterapkan sekali dan urutan disimpan. Kunci tidak dikirim ke peserta. Soal dan gambar hanya dikirim kepada pemilik pengerjaan dengan sesi yang sah.
3. Memilih atau mengosongkan jawaban mengirim perubahan ke server. Tunggu **Tersimpan di server**; jika gagal atau konfirmasi hilang, jawabannya **belum dapat dianggap aman**. Gunakan **Coba simpan lagi** atau **Muat ulang untuk memeriksa** setelah koneksi pulih. Percobaan ulang untuk respons yang hilang bersifat idempoten; konflik dengan tab/perangkat lain meminta muat ulang, bukan diam-diam menimpa. JavaScript dan koneksi ke server diperlukan untuk menyimpan; tanpa JavaScript pilihan dinonaktifkan.
4. Centang **Ragu-ragu** pada soal yang perlu ditinjau, baik sudah maupun belum dijawab; tanda ini tidak menghapus atau mengubah nilai jawaban. Tunggu konfirmasi server seperti pada penyimpanan jawaban. Tanda tetap ada saat berpindah soal atau melanjutkan tes dan hanya hilang jika dicabut. Navigasi/progres memakai kategori warna yang saling eksklusif: hijau terjawab tanpa tanda, kuning ragu (dapat sudah/belum dijawab), abu-abu belum dijawab tanpa tanda; garis menunjukkan soal aktif. Jumlah terjawab mencakup soal bertanda ragu yang memiliki jawaban. Pada soal panjang, panel nomor tetap dekat di desktop; di layar kecil nomor tersedia pada bilah yang dapat digeser pada header.
5. Jika keluar atau masuk kembali sebelum batas akhir, pilih **Lanjutkan tes** pada jadwal yang terlihat hari ini atau berlanjut dari kemarin. Pengerjaan, urutan, jawaban, dan tanda ragu yang tersimpan tetap sama; waktu tidak diulang dan token tidak diminta lagi. Login pada perangkat lain mengakhiri sesi perangkat sebelumnya. Tombol kembali ke jadwal tidak ditampilkan saat pengerjaan aktif; ini bukan kunci perangkat atau pencegah pengguna keluar melalui browser.
6. Admin mengatur **Data Tes → Pengaturan Pengerjaan**: jumlah menit terakhir yang mengizinkan pengumpulan manual, awalnya **5**, antara 1–10080 menit. Satu nilai berlaku untuk semua tes dan segera berlaku juga pada pengerjaan yang sedang berjalan. Jika nilainya lebih besar dari waktu tersisa, peserta dapat mengumpulkan segera. Peserta boleh menekan **Selesaikan tes** kapan saja; server memeriksa nilai terkini dan waktu database, lalu memberi peringatan jika terlalu awal atau konfirmasi jumlah terjawab, kosong dan ragu jika sudah memenuhi syarat. Setelah dikumpulkan, pengerjaan tidak dapat diubah.
7. Pada batas akhir server menolak jawaban baru dan menyelesaikan berdasarkan jawaban terakhir yang berhasil tersimpan, termasuk jawaban yang masih bertanda ragu. Proses latar belakang pada layanan Node memeriksa pengerjaan kedaluwarsa tanpa bergantung pada browser. Jika aplikasi/database berhenti, penyelesaian dan tampilan status dapat tertunda hingga layanan pulih; batas waktu tidak diperpanjang. Jalankan layanan Node terus-menerus, bukan deployment serverless yang ditidurkan. Cadangkan database beserta gambar; snapshot dan nilai tidak dienkripsi oleh aplikasi.
8. Admin membuka **Data Tes → Hasil / Monitoring Tes** dan memuat ulang untuk status dan nilai pengerjaan. Nilai dasar adalah **100 × jumlah benar ÷ jumlah soal**; salah dan kosong bernilai nol, tanpa penalti. Tampilan dua desimal, pembulatan setengah ke atas; jumlah benar, terjawab dan soal tersimpan untuk pemeriksaan. Status yang lewat batas tetapi belum diproses ditandai **Menunggu penyelesaian**.
9. Nilai peserta **tersedia secara default setelah pengerjaan selesai** untuk kategori Reguler, Susulan, dan Remidi, termasuk hasil lama setelah migrasi `021`. Admin mengubahnya secara global per kategori di **Data Tes → Pengaturan Pengerjaan → Visibilitas nilai peserta**, bukan per tes; perubahan berlaku langsung untuk seluruh tes pada kategori tersebut. Peserta hanya menerima nilai pengerjaannya yang sudah selesai; kunci dan jumlah benar tidak dibagikan. Angka mula-mula disamarkan: tekan **Perlihatkan nilai** untuk melihatnya, atau **Samarkan nilai** untuk menutup kembali. Samaran hanyalah tampilan, **bukan pengamanan**: nilai yang diizinkan sudah dikirim ke browser. Tutup dan buka ulang modal atau muat ulang untuk mengambil kebijakan terbaru. Menyembunyikan kembali mencegah pengiriman pada permintaan berikutnya, tetapi tidak dapat menarik nilai yang telah diterima, dilihat, atau disalin.
10. Pada jadwal hari ini, **Lihat status pengerjaan** membuka modal tanpa meninggalkan `/peserta`; **Lanjutkan tes** tetap membuka pengerjaan yang belum selesai. Tombol **Nilai dibagikan** menunjukkan nilai yang diizinkan untuk periode login aktif, termasuk dari hari sebelumnya tanpa mengembalikan jadwal lama. Tanpa JavaScript, tautan cadangan membuka halaman status/nilai terpisah. Semua admin dapat mengubah pengaturan ini; perubahan terakhir mencatat admin/waktu, bukan riwayat audit lengkap.

### Izin mengulang dalam pelaksanaan yang sama — pratinjau

1. Setelah migrasi `022`, buka **Data Tes → Hasil / Monitoring Tes**. Gunakan **filter monitoring**: cari tes dari saran pencarian (kosongkan untuk semua tes), pilih tahun ajaran, kelas/rombel, kategori tes (Reguler/Susulan/Remidi), status peserta (Belum mulai, Mengerjakan, Menunggu penyelesaian, Dikumpulkan, Waktu habis), rentang tanggal berdasarkan waktu mulai **jadwal pelaksanaan** dalam zona yang dipilih (WIB/WITA/WIT; tanggal akhir inklusif), serta urutan (waktu, nilai, nama peserta, nama tes). Satu baris mewakili satu pengerjaan, termasuk peserta terdaftar yang belum mulai. Peserta, nomor, kelas, periode, tahun ajaran, pelaksanaan, nomor pengerjaan, nilai, status dan status izin ditampilkan. Tombol **Ekspor .xlsx** mengunduh seluruh hasil filter (maksimal 5.000 baris; sempitkan filter bila melebihi batas) dengan lembar Monitoring dan Informasi. Pada **pengerjaan terakhir yang sudah selesai**, selama jadwal masih berlangsung, pilih **Berikan izin ulang** dan konfirmasikan. Tidak bisa memberi izin ketika pengerjaan terakhir masih aktif, menunggu penyelesaian, atau waktunya telah habis. Semua admin bersesi sah dapat memberi izin; peran operator khusus belum tersedia.
2. **Satu izin untuk satu pengulangan.** Peserta memuat ulang jadwal, memilih **Mulai ulang tes**, dan memasukkan token enam digit yang sedang berlaku. Pengulangan memakai isi/snapshot, kunci, gambar dan urutan soal/pilihan pengerjaan sebelumnya; **jawaban dan tanda ragu mulai kosong**. Deadline tetap deadline awal, jadi hanya waktu yang tersisa yang tersedia, bukan tambahan durasi. Jika peserta baru mulai ketika deadline berakhir, izin tidak dapat dipakai. Memuat ulang setelah mulai melanjutkan pengerjaan yang sama; token tidak diperlukan lagi untuk melanjutkan.
3. **Pengumpulan manual tetap memakai batas global**, awalnya **lima menit terakhir**. Dengan pengaturan awal, jika pengerjaan sebelumnya baru dapat dikumpulkan pada lima menit terakhir, pengulangan hanya memperoleh waktu yang tersisa dalam lima menit itu. Admin dapat mengubah batas global sebelum pelaksanaan bila diperlukan, tetapi perubahan itu berlaku untuk **semua pengerjaan yang sedang berjalan**, bukan hanya peserta ini. Pemberian izin tidak menyelesaikan pengerjaan aktif secara paksa dan tidak mengulang jam; pengumpulan otomatis saat deadline tetap berlaku.
4. Admin dapat memilih **Cabut izin** sebelum izin digunakan. Setelah dipakai, izin tidak dapat dicabut; pengerjaan baru tetap berjalan. Jika izin dicabut, admin dapat secara sengaja memberi izin baru selama syarat masih terpenuhi. Setelah pengulangan selesai dan masih ada waktu, izin berikutnya harus diberikan secara terpisah pada pengerjaan terbaru; pengiriman ulang formulir lama tidak memberi izin berikutnya. Monitoring menunjukkan status izin terakhir untuk tiap pengerjaan: tersedia, digunakan, dicabut, atau kedaluwarsa. Catatan izin lama dan seluruh pengerjaan, jawaban, serta nilai tetap disimpan; daftar monitoring dipaginasi.
5. Jika respons tindakan admin hilang atau hasil belum pasti, pada **tab yang sama** pilih **Periksa dan amankan**. Server melaporkan tindakan yang sempat berhasil atau memagari permintaan yang belum berhasil agar tidak mengubah izin jika datang terlambat. Muat ulang dan periksa status terkini setelahnya; status bisa berubah jika peserta/admin lain bertindak. Tab hanya menyimpan identitas permintaan, bukan token. Jangan tutup tab atau hapus data sesi browser sebelum selesai; jika identitas hilang, **reload saja tidak menjamin request terlambat telah diamankan**—hubungi pengelola teknis sebelum tindakan lain. Jika sesi admin berakhir, masuk kembali di tab yang sama dan selesaikan pemeriksaan. Aksi izin admin memerlukan JavaScript; peserta tetap memiliki formulir cadangan tanpa JavaScript.
6. Nilai setiap pengerjaan tetap terpisah dan dapat ditampilkan kepada pemilik sesuai visibilitas kategori, termasuk sebelum nilai akhir ditetapkan. Pelaksanaan susulan/remidi lain tetap dipilih dan dirilis terpisah, tetapi penetapan nilai akhir menutup mulai baru untuk **semua** pelaksanaan tes tersebut bagi peserta itu. Setelah pengerjaan dibuat, jadwal tidak dapat ditarik rilis atau dihapus. Jangan mengubah database langsung sebagai jalan pintas untuk mengulang atau menghapus riwayat.

### Nilai akhir per tes dan peserta — pratinjau

1. Setelah migrasi `023`, buka **Data Tes → Hasil / Monitoring Tes**, pilih satu tes pada filter, lalu **Terapkan**. Panel **Nilai akhir** mengelompokkan semua pengerjaan milik identitas peserta dalam periode tes itu. Hanya peserta yang sudah memiliki pengerjaan muncul; daftar nilai akhir dan daftar pengerjaan memiliki halaman masing-masing. Status **Sementara** adalah pratinjau admin dan belum dibagikan sebagai nilai akhir.
2. Metode awal adalah **Tertinggi**. Pilih **Ubah metode** untuk beralih ke **Rata-rata** atau kembali. Rata-rata memberi bobot sama kepada **setiap pengerjaan selesai**, bukan kepada setiap soal. Semua pengerjaan selesai Reguler, Susulan, Remidi dan pengulangan untuk tes/peserta yang sama termasuk. Nilai dihitung dari jumlah benar/jumlah soal tanpa merata-ratakan angka tampilan; hasil akhir dibulatkan dua desimal, setengah ke atas. Contoh 60 dan 80 menjadi tertinggi 80 atau rata-rata 70. Penggantian metode **langsung menghitung ulang semua nilai akhir yang sudah ditetapkan untuk tes itu**, termasuk yang sudah dibagikan; dialog memperingatkan dan tindakan dicatat.
3. Periksa peserta, jumlah pengerjaan dan nilai, lalu pilih **Tetapkan nilai akhir** dan konfirmasi. Minimal satu pengerjaan selesai diperlukan. Jika masih ada pengerjaan belum selesai, termasuk lewat deadline tetapi **Menunggu penyelesaian**, penetapan ditolak; tunggu proses otomatis dan muat ulang. Penetapan menutup mulai pertama pada pelaksanaan lain dan mulai ulang pada seluruh kategori untuk peserta/tes ini; tidak menutup tes atau peserta lain. Semua izin mengulang yang belum digunakan, termasuk yang sudah kedaluwarsa, **dicabut** dalam transaksi yang sama. Riwayat pengerjaan, jawaban, nilai dan izin tetap ada. Permintaan/formulir lama tidak otomatis berlaku setelah status berubah.
4. **Buka kembali** meminta konfirmasi dan mengembalikan nilai akhir menjadi sementara; mulai baru dapat dilakukan lagi sesuai jadwal, token dan izin. Izin yang dicabut saat penetapan tidak hidup kembali; admin harus memberi izin baru jika diperlukan. Pengerjaan lama tetap dapat dilihat sesuai kebijakannya. Setelah pengerjaan tambahan selesai, periksa dan tetapkan lagi secara sengaja.
5. Peserta tetap dapat melihat nilai per pengerjaan yang selesai sesuai pengaturan kategori, termasuk sebelum penetapan. Nilai akhir hanya dikirim setelah ditetapkan **dan semua kategori yang benar-benar menyumbang sedang dibuka** di **Pengaturan Pengerjaan**; kategori yang tidak menyumbang tidak menghalangi. Jika satu penyumbang ditutup atau nilai dibuka kembali, nilai akhir tidak dikirim pada permintaan berikutnya; tidak ada agregasi sebagian. Penyamaran nilai di browser hanya tampilan, bukan pengamanan, dan informasi yang pernah diterima tidak dapat ditarik kembali. Dialog **Nilai dibagikan** dan halaman cadangan tanpa JavaScript memakai aturan yang sama.
6. Tindakan metode, penetapan dan pembukaan kembali dicatat dengan admin/waktu, serta nilai, metode dan ID pengerjaan penyumbang saat penetapan/pembukaan; nilai tercatat ini bukan sumber perhitungan. Monitoring menampilkan **20 tindakan terbaru** untuk tes yang dipilih. Jejak metode/pagar tetap tersimpan jika tes draf dihapus, tetapi panel tes yang dihapus tidak lagi tersedia. Audit di database **bukan log kebal-ubah** bagi pengelola database dan bukan audit keamanan menyeluruh. Semua admin bersesi sah dapat menggunakan tindakan ini; hak operator khusus belum tersedia.
7. Tindakan admin memerlukan JavaScript. Jika hasil tidak pasti, tetap di **tab yang sama**, pilih **Periksa dan amankan**, lalu muat ulang dan periksa status terkini. Jika sesi admin berakhir, masuk lagi di tab yang sama. Jangan tutup tab atau hapus penyimpanan sesi sebelum pemeriksaan selesai; identitas request yang hilang tidak dapat dipulihkan hanya dengan reload. Data yang dikirim ke perangkat peserta tidak dapat ditarik kembali.

### Rekap hasil tes dan Excel — pratinjau

1. Buka **Laporan → Rekap Hasil Tes**. Matriks menampilkan **siswa sebagai baris dan tes sebagai kolom**. Hanya pengerjaan selesai yang cocok dengan seluruh filter yang dihitung, memakai metode tes (tertinggi atau rata-rata) untuk sel tersebut; hasil dapat berbeda dari nilai akhir yang ditetapkan dan tidak mengubahnya. Peserta/tes tanpa pengerjaan selesai yang cocok tidak muncul.
2. Filter dapat menggabungkan tahun ajaran, periode, tes, **kelas/rombel** (nama snapshot persis) dan pencarian nama (snapshot), nomor peserta (snapshot) atau NISN (saat ini), serta jenis ujian **Reguler, Susulan atau Remidi** (awalan Reguler). Pilihan **Gabungkan nilai Reguler + Susulan** hanya tersedia pada jenis Reguler. Rentang memakai tanggal **waktu selesai** dalam zona WIB, WITA atau WIT; tanggal akhir inklusif dan data tahun 2000–2100 dapat dijadikan batas. Tanpa batas tanggal, semua waktu selesai disertakan.
3. Saat gabung, nilai sel dari Susulan berwarna biru muda; bila Reguler dan Susulan sama-sama ada untuk siswa/tes yang sama, sel ditandai **Periksa**, tidak dihitung sebagai angka, dan tautannya membuka monitoring tes tersebut. Rata-rata hanya dihitung dari nilai tes yang tersedia, bukan nol untuk sel kosong atau bentrok. Jumlah tes yang dihitung dan jumlah bentrok ditampilkan pada kolom **Rata-rata**.
4. Nama, kelas dan tahun pada baris memakai snapshot cocok terbaru; NISN memakai data siswa saat ini; nama tes adalah snapshot cocok terbaru dengan nama periode di bawahnya. Siswa dikelompokkan per ID siswa dan tahun ajaran, sehingga siswa yang sama pada tahun berbeda muncul terpisah.
5. Batas tampilan dan ekspor: **2.000 siswa**, **59 kolom tes**, **10.000 pengerjaan** cocok dengan filter. Bila melebihi, peringatan ditampilkan dan hasil/file parsial **tidak dikirim**. Halaman dipaginasi 30 siswa.
6. **Unduh Excel** menghasilkan `.xlsx` untuk seluruh hasil filter, bukan hanya halaman yang terlihat, dengan lembar **Rekap**, **Pengerjaan**, dan **Informasi**. Lembar Rekap memuat judul, metadata filter, pita **DAFTAR NAMA TES**, header beku dan filter otomatis. Waktu disajikan sebagai teks dalam zona laporan. NISN/nomor disimpan sebagai teks dan nilai sebagai angka; teks diperlakukan sebagai teks literal, bukan rumus Excel. Susulan dan sel **Periksa** diberi warna. Tidak ada formula, tautan eksternal, atau makro.
7. Semua admin bersesi sah dapat melihat dan mengunduh laporan, termasuk nilai yang belum dibagikan ke peserta. File berisi identitas dan nilai serta **tidak dienkripsi oleh aplikasi**; simpan dan bagikan hanya melalui tempat/perangkat yang aman, gunakan HTTPS tepercaya, dan jangan taruh file di repository. Tidak ada audit khusus untuk setiap unduhan, hak operator terpisah, cetak, atau ekspor PDF pada tahap ini. Kinerja data besar dan keamanan menyeluruh tetap perlu diuji.

Fitur rekap ini tidak menambah migrasi sendiri, tetapi memerlukan skema sampai `024` (tahun ajaran menjadi filter rekap). `fflate` versi yang telah terkunci adalah dependensi runtime; gunakan `npm ci` dengan lockfile terbaru di lingkungan yang disiapkan (perintah mengganti `node_modules`) sebelum build jika dependensi instalasi belum sesuai.

Untuk token mulai, lima kode salah berformat benar mengunci identitas selama 15 menit; belum ada tombol buka kunci token. Batas tambahan 60 kegagalan per menit bersifat global pada database dan dapat menghambat semua peserta, bukan proteksi per IP. Pembatas ini dapat disalahgunakan dan belum menggantikan perlindungan jaringan, audit serta uji keamanan dan beban pada lingkungan sasaran.

### Token — pengelolaan admin

1. Setelah migrasi dan penyiapan **kunci token terpisah** di bawah, buka **Data Tes → Token**. Token global berada di atas. Daftar token khusus menampilkan satu baris per tes dengan pelaksanaan berlangsung/mendatang yang cocok dengan tanggal, termasuk draf; jika belum ada pelaksanaan, daftar menggunakan jadwal dasar rancangan untuk kompatibilitas tes lama. Default **hari ini**, mengikuti zona WIB/WITA/WIT yang dipilih (awal: WIB); pilih tanggal lain atau **Semua tanggal**. Jadwal yang melintasi hari itu disertakan. Daftar dipaginasi 20 tes per halaman dan jadwal berlangsung didahulukan. Jika seluruh jadwal telah berakhir, tes tidak muncul tetapi riwayat tetap tersedia. Label berlangsung menunjukkan waktu, bukan bahwa peserta sudah dapat mengerjakan.
2. Pilih durasi **5, 15, atau 30 menit; 1, 2, atau 6 jam; atau 1 hari**, lalu aktifkan token global atau token khusus pada baris tes. Masa aktif dimulai **segera** saat diterbitkan, termasuk untuk tes mendatang. Kode baru berupa enam digit acak; nol di depan penting. Hitung mundur dan zona WIB/WITA/WIT ditampilkan menurut perkiraan jam server; muat ulang setelah perubahan oleh admin lain. Server memeriksa waktu dan revisi lagi ketika mengubah data.
3. Kode yang tidak aktif diredupkan dan diberi tanda **tidak berlaku**; tombol salin hanya tersedia pada kode yang aktif. Status berubah ketika waktu habis. Melalui **Lihat riwayat**, admin dapat membuka halaman terpisah untuk meninjau catatan; kode baru tetap terbaca termasuk setelah kedaluwarsa atau dicabut. Bila jadwal tes kini sudah berakhir, riwayat menandainya tidak berlaku meskipun masa token belum habis. Riwayat dipaginasi dan tidak dihapus otomatis setelah satu hari. **Kode lama sebelum fitur enam digit tidak dapat dipulihkan**, karena hanya hash yang disimpan, tetapi metadata dan statusnya tetap ada. Penghapusan tes melepaskan token khusus tanpa mengubah scope menjadi global; riwayat tetap ada.
4. Setiap cakupan memiliki paling banyak satu slot belum ditutup. **Token khusus melekat pada tes induk dan sama untuk semua sesi reguler, susulan, dan remidi**, bukan token terpisah untuk setiap pelaksanaan; masa aktif tetap dimulai saat token diterbitkan. Membuat token baru menggantikan slot lama; mengganti token yang masih aktif dan **Cabut** memerlukan konfirmasi. Kode yang baru diterbitkan menghindari benturan dengan slot terbuka dan kode tujuh hari terakhir, tetapi karena hanya ada satu juta kombinasi, kode dapat terulang di masa depan. Gunakan ID token, scope, dan waktu untuk membedakan riwayat.
5. Jika hasil pembuatan tidak pasti, pilih **Periksa dan amankan** pada tab yang sama. Server melaporkan bila token sempat dibuat atau memagari permintaan agar tidak dapat membuat token terlambat; kode baru yang sudah tersimpan dapat dilihat setelah reload bila kunci tersedia. Halaman menyimpan hanya UUID permintaan, bukan kode, di penyimpanan sesi tab. **Jangan tutup tab atau hapus data sesi sebelum pemeriksaan selesai.** Jika identitas permintaan hilang, reload saja tidak menjamin request terlambat tidak akan masuk; hubungi pengelola teknis.
6. Saat mulai, **token khusus tes yang aktif mengesampingkan global** untuk tes itu. Setelah khusus berakhir atau dicabut, global yang masih aktif dapat digunakan kembali. Pencabutan global tidak memengaruhi token khusus. Token diperiksa saat mulai saja, bukan syarat tetap aktif selama pengerjaan.

#### Kunci untuk token

Kode baru disimpan sebagai **AES-256-GCM** terenkripsi dan HMAC berkunci, bukan plaintext atau hash enam digit yang mudah ditebak dari database. Gunakan file kunci acak yang **berbeda dari kunci sandi peserta** dan berada di luar proyek/repository dan database. Contoh Windows, setelah folder aman disiapkan:

```powershell
npm run token:key:create -- 'C:\ProgramData\NusaCBT\keys\exam-token.key'
```

Perintah membuat file sekali dan menolak menimpa file yang sudah ada. Atur izin folder/file agar hanya akun layanan dan pengelola berwenang dapat membacanya; di Windows atur ACL NTFS. Tambahkan hanya **path** pada `.env.local`, misalnya `NUSACBT_EXAM_TOKEN_KEY_FILE=C:/ProgramData/NusaCBT/keys/exam-token.key`, lalu restart aplikasi. Jika kunci sandi peserta juga dikonfigurasi, file itu harus dapat dibaca dan isinya harus berbeda. Seluruh proses aplikasi yang memakai database yang sama harus menggunakan kunci token yang sama.

**Cadangkan kunci token secara aman dan terpisah dari database**, dan uji pemulihan keduanya di lingkungan terisolasi. Database mengikat kunci saat token enam digit pertama dibuat; kunci yang salah ditolak. Jika kunci hilang, kode terenkripsi tidak dapat dibuka. Rotasi dan pemulihan kunci hilang belum tersedia: jangan menimpa file lama, menghapus pengikat, atau mengganti kunci secara sembarangan. Token aktif tetap dapat dicabut bila kunci tidak tersedia.

**Penting:** token baru terlihat terus di halaman admin dan dikirim ke browser admin. Gunakan HTTPS tepercaya, perangkat aman dan proxy yang tidak mencatat isi permintaan/respons; jangan bagikan kode di kanal publik. Enam digit hanya memiliki satu juta kemungkinan dan mudah ditebak. Pemeriksaan mulai dan pembatas dasar sudah tersedia, tetapi bukan perlindungan menyeluruh: pengujian keamanan, beban dan operasional pada lingkungan sasaran tetap diperlukan. Jangan gunakan data nyata sebelum semuanya siap.

### Tahun ajaran dan perpindahan siswa — pratinjau

1. **Tahun ajaran adalah induk periode dan roster siswa.** Buka **Data Peserta → Tahun Ajaran**. Buat tahun dengan format dua tahun berurutan, misalnya `2026/2027`; nama unik tanpa membedakan huruf besar/kecil. Satu tahun dapat diaktifkan pada satu waktu, atau tidak ada tahun aktif. Mengaktifkan tahun lain atau menonaktifkan tahun **mengakhiri semua sesi peserta dan menonaktifkan login periode lama**; akun, sandi, roster, jadwal, pengerjaan dan nilai tidak dihapus. Tahun lama tetap dapat dilihat.
2. **Periode ujian berada di dalam tahun ajaran.** Nama dan tanggal mulai periode wajib diisi; tanggal akhir opsional dan tidak boleh lebih awal dari tanggal mulai. Login hanya dapat diaktifkan untuk periode yang berada pada tahun ajaran yang sedang aktif; setelah pergantian tahun, aktifkan periode login baru secara manual. Periode lama yang belum dipetakan menampilkan peringatan dan tidak dapat diaktifkan loginnya.
3. **Petakan periode lama secara eksplisit.** Pada **Periode Ujian**, ubah periode lama dan pilih tahun ajarannya. Sistem memeriksa konflik kelas/status antara penempatan aktif periode dan roster tahun tujuan; jika ada perbedaan, perubahan ditolak dan tidak ada data yang diubah. Bila tidak ada konflik, siswa aktif periode ditambahkan ke roster tahun sebagai riwayat `legacy`. Tahun periode yang sudah dipetakan tidak dapat diganti otomatis.
4. **Roster siswa dikelola per tahun ajaran.** Buka **Data Peserta → Data Siswa**. Setiap siswa tercatat paling banyak sekali per tahun dengan status **Aktif**, **Lulus**, atau **Keluar** dan kelas/rombelnya. Penempatan aktif pada periode disediakan untuk setiap periode dalam tahun yang sama, sehingga siswa aktif tahun tidak perlu didaftarkan ulang per periode. Identitas dan sandi tetap dibuat per periode.
5. **Perpindahan (rollover) ke tahun baru.** Di **Tahun Ajaran**, pilih tahun asal dan tahun tujuan, lalu periksa pratinjau. Sistem mengusulkan X → XI dan XI → XII pada jurusan yang sama jika kelas tujuan tersedia; kelas XII dan kelas tanpa usulan harus ditentukan sendiri. Hanya siswa berstatus aktif pada tahun asal yang disertakan. Pilih **Naik kelas**, **Tinggal kelas**, **Lulus**, atau **Keluar** untuk setiap siswa, lengkapi kelas tujuan untuk yang naik/tinggal, lalu **Periksa dan simpan perpindahan** dan konfirmasi.
6. **Siswa yang sudah tercatat pada tahun tujuan tidak ditimpa.** Baris tersebut ditandai "Sudah ada di tujuan" dan keputusan disimpan sebagai "Data tujuan dipertahankan". Siswa lulus/keluar tercatat sebagai riwayat dan tidak ditempatkan pada periode tujuan. Data sumber tidak dihapus; perubahan dapat diperiksa kembali di roster tahun asal dan tujuan. Pratinjau kedaluwarsa bila data berubah; muat ulang dan periksa kembali.
7. Perubahan kelas/status pada roster tahun dapat mengakhiri sesi peserta pada periode tahun tersebut; riwayat tes tetap disimpan. Kumpulan siswa dan kelas baru yang sudah `Lulus`/`Keluar` tidak menghasilkan penempatan periode dan tidak dapat login sampai statusnya diubah kembali secara manual (tidak tersedia sebagai rollover massal; lakukan satu per satu di Data Siswa).

Semua admin bersesi sah dapat mengelola tahun ajaran; peran operator khusus belum tersedia. Fitur memerlukan skema sampai `024`.

### Data peserta

Pada **Data Peserta → Kelas / Jurusan**, admin mengelola daftar jurusan terpisah, lalu membuat kelas dari tingkat dan jurusan, misalnya `X AK`. Nama jurusan tidak boleh sama tanpa membedakan huruf besar/kecil, dan satu kombinasi tingkat–jurusan hanya dapat dibuat sekali. Jurusan yang masih digunakan oleh kelas tidak dapat dihapus.

Pada **Data Peserta → Data Siswa**, admin dapat menambah, mencari, dan mengubah siswa secara manual, mengelola nama/NISN, serta mengatur kelas dan status per tahun ajaran. Nama dan NISN wajib diisi; NISN harus unik dan tepat 10 digit, disimpan sebagai teks. Nama siswa yang baru atau disimpan ulang menjadi **HURUF KAPITAL**; nama lama tidak diubah otomatis. Konversi Unicode dapat memperpanjang atau mengubah bentuk beberapa huruf, sehingga batas 100 karakter diperiksa setelah konversi. Identitas siswa berlaku lintas tahun ajaran, sehingga perubahan nama/NISN terlihat di semua tahun. Penambahan siswa ke tahun, perpindahan kelas/status, dan penempatan pada periode disinkronkan melalui roster tahun ajaran.

Mengganti kelas atau mengakhiri keikutsertaan menyimpan catatan lama sebagai riwayat. Nama kelas dicatat ketika penempatan/roster dibuat; perubahan nama jurusan atau kelas tidak menulis ulang nama pada riwayat tersebut. Waktu riwayat menunjukkan kapan perubahan dicatat, dalam UTC, bukan tanggal efektif perpindahan sekolah. Siswa, kelas, periode, dan tahun yang memiliki riwayat tidak dapat dihapus, termasuk jika penempatannya sudah berakhir; penghapusan permanen riwayat belum tersedia.

### Impor siswa dari Excel

1. Siapkan tahun ajaran, periode serta kelas/jurusan di aplikasi. Buka **Data Peserta → Import Data Peserta** dan unduh template fiktif. Hapus baris contoh sebelum digunakan.
2. Pada sheet `Peserta`, gunakan urutan kolom `Nomor`, `Nama`, `NISN`, `Kelas`. Nomor hanya nomor urut. Isi nama, NISN, dan kelas yang sudah ada; cocokkan nama kelas dengan daftar kelas. Pilih satu **tahun ajaran** untuk seluruh file; impor membuat/menempatkan roster tahun ajaran, bukan penempatan periode langsung.
3. **Sel NISN harus berupa teks** berisi tepat 10 digit. Jangan mengandalkan format angka dengan nol tampilan: nol yang sudah hilang tidak dapat dipulihkan dengan aman. Kolom NISN pada template disiapkan sebagai teks untuk baris 2–1001; saat menempel data, pastikan format teks tetap terjaga.
4. Pilih file `.xlsx` maksimal 512 KB dan 1.000 baris data. Rumus pada nama/NISN/kelas, sel gabungan, baris data tersembunyi, serta data pada kolom tambahan tidak didukung. Baris yang tidak memiliki isi pada kolom selain Nomor diabaikan.
5. Klik **Periksa pratinjau**. Duplikat NISN dalam file, data tidak valid, kelas yang tidak ditemukan/ambigu, serta konflik dengan siswa lama harus diperbaiki seluruhnya sebelum penyimpanan. Nama siswa baru ditampilkan dan disimpan dalam huruf kapital; batas 100 karakter berlaku setelah kapitalisasi. Nama siswa lama dicocokkan setelah spasi tepi dibuang, normalisasi Unicode, dan kapitalisasi; perbedaan kapitalisasi saja tidak menjadi konflik dan nama lama tetap seperti tersimpan. Nama lama yang cocok tetap dapat digunakan meski hasil kapitalisasi Unicode melebihi batas nama baru, karena namanya tidak ditulis ulang. Kelas dicocokkan tanpa membedakan huruf besar/kecil dan kelebihan spasi.
6. Jika nama siswa lama sesuai dan belum ada kelas aktif pada tahun ajaran tersebut, penempatan tahun baru ditambahkan. Jika kelas aktif sudah sama, baris tidak mengubah apa pun. Nama atau kelas aktif yang berbeda **tidak ditimpa**; perbaiki file atau kelola data secara manual. Siswa berstatus lulus/keluar pada tahun ini ditolak dan harus diperiksa/manual diatur kembali. Setelah konfirmasi, semua perubahan disimpan dalam satu transaksi. Bila data berubah sejak pratinjau, periksa ulang file.

Aplikasi tidak menyimpan berkas impor ke repository. Impor **tidak** membuat atau mengubah nomor peserta, username, kata sandi, atau kartu. Atur identitas secara terpisah setelah impor. Gunakan data fiktif sampai pengujian keamanan dan operasional selesai.

### Nomor peserta dan username

1. Buka **Data Peserta → Akun Peserta**, lalu pilih satu periode. Identitas, sandi tersamarkan, dan status penguncian ditampilkan dalam satu daftar. Daftar mencakup siswa yang memiliki kelas aktif pada periode tersebut, serta identitas yang tersimpan meskipun kelasnya tidak lagi aktif. Tautan lama `/data-peserta/identitas` dan `/data-peserta/sandi` tetap dapat dibuka.
2. Pilih **Atur identitas** untuk mengisi nomor dan username sekaligus, atau **Ubah identitas** untuk mengubahnya secara sengaja. Keduanya berupa teks dan boleh sama atau berbeda. Nomor 1–64 karakter; username 3–64 karakter. Karakter awal harus huruf atau angka ASCII; setelahnya boleh juga titik, garis bawah, atau tanda hubung. Nol di depan dipertahankan.
3. Nomor peserta harus unik dalam periode dan username juga harus unik dalam periode, **tanpa membedakan huruf besar/kecil**. Nilai yang sama boleh digunakan lagi pada periode lain. Nomor dan username masing-masing mempunyai aturan unik tersendiri; satu nilai boleh menjadi nomor seorang siswa dan username siswa lain.
4. **Buat identitas otomatis** menawarkan konfirmasi untuk siswa dengan kelas aktif yang **belum memiliki pasangan identitas**. Tombol ini tidak dipengaruhi pencarian dan tidak pernah mengubah identitas yang sudah ada. Maksimal 1.000 siswa diproses dalam sekali batch, menurut urutan nama; bila masih ada, ulangi setelah daftar diperbarui. Untuk menggabungkan nilai otomatis dan nilai manual, buat pasangan otomatis lalu ubah salah satunya secara sengaja.
5. Pola awal untuk keduanya adalah `{prefix}{YYYYMM}{acak3}`. `{YYYYMM}` berasal dari tanggal mulai periode dan `{acak3}` adalah angka acak `000`–`999`. Prefix opsional; pola nomor dan username dapat diubah terpisah. Setiap pola wajib berisi `{acak3}` tepat sekali; `{prefix}` dan `{YYYYMM}` boleh digunakan masing-masing sekali. Pola yang sama menghasilkan nomor dan username yang sama; pola berbeda menghasilkan nilai secara terpisah. Maksimal 1.000 kombinasi untuk satu pola yang sudah diisi prefix dan bulan; nilai yang sudah dipakai mengurangi kapasitas. Jika tidak cukup atau data berubah saat penyimpanan, seluruh batch dibatalkan.
6. Saat penempatan diakhiri, identitas tetap tersimpan dan nilainya tetap digunakan di periode tersebut; kembalikan penempatan kelas untuk mengubahnya. Siswa dan periode yang memiliki identitas juga tidak dapat dihapus. Setelah migrasi `015`, identitas, sandi, dan kelas aktif dapat digunakan untuk login peserta pada periode yang diaktifkan admin.

### Cetak kartu peserta — pratinjau A4

1. Kartu selalu memakai **periode login aktif**; tidak ada pemilih periode pada halaman ini. Aktifkan periode login yang sesuai di **Data Peserta → Periode Ujian** sebelum menyiapkan kartu. Secara opsional, pilih kelas aktif dan/atau cari siswa berdasarkan nama, NISN, nomor peserta, atau username. Baris tanpa identitas ditandai dan tidak dapat dipilih; atur identitas di **Akun Peserta**. Akun tanpa sandi dapat dipilih untuk kartu **tanpa** sandi, tetapi belum dapat dipakai login sampai sandinya dibuat. Kelas yang dicetak adalah nama kelas aktif saat kartu disiapkan, bukan snapshot kelas pada jadwal.
2. Daftar hanya mencakup siswa berkelas aktif pada periode login aktif. Setelah mengubah filter, klik **Terapkan** dan pilih kembali.
3. Pilih satu atau beberapa siswa, atau **Pilih semua yang beridentitas pada halaman ini** untuk mencetak per kelas. Maksimal **100 kartu per batch**; jika hasil lebih dari 100, cetak halaman berikutnya secara terpisah. Pilihan tidak terbawa antarhalaman dan tidak otomatis mencakup siswa yang ditambahkan setelah daftar dimuat. Periksa jumlah, nama, kelas, nomor, dan username.
4. Secara default **sandi tidak disertakan**. Bila benar-benar perlu, centang **Sertakan sandi pada kartu**, lalu konfirmasi. Semua peserta terpilih harus sudah memiliki sandi dan file kunci peserta yang cocok harus tersedia; jika satu gagal, seluruh batch ditolak tanpa mengirim sandi. Setiap sandi yang berhasil disiapkan dicatat sebagai `reveal` bersama peserta, admin, dan waktu, tanpa nilai rahasia. Catatan tetap ada bila cetak dibatalkan atau respons terputus sesudah commit; tidak menunjukkan bahwa kertas benar-benar dicetak. Tidak ada audit untuk kartu tanpa sandi atau setiap lembar cetak.
5. Pada pratinjau, gunakan **Cetak / Simpan PDF**, pilih **A4, potret**, dan periksa pratinjau browser sebelum mencetak. Pilih tujuan **Simpan sebagai PDF** bila diinginkan; aplikasi tidak membuat atau mengenkripsi PDF sendiri. Tombol memeriksa ulang sesi, identitas, sandi, kelas, dan kecocokan filter sebelum membuka dialog. Jika data berubah, muat ulang dan pilih kembali. Perubahan setelah pemeriksaan tidak dapat ditarik kembali dari pratinjau browser, file, atau printer. Ctrl+P dari pratinjau diblokir pada browser yang mendukung event cetak; jangan andalkan pemblokiran ini sebagai pembatas keamanan, dan selalu gunakan tombol tersebut.
6. Aplikasi berupaya menutup pratinjau setelah event dialog cetak selesai, setelah lima menit selama JavaScript berjalan, atau ketika tab disembunyikan di luar dialog cetak/ditinggalkan; untuk mencetak ulang siapkan kembali. Kartu disiapkan untuk periode yang sedang aktif; bila periode login berbeda pada saat kartu dipakai, kelas aktif, periode aktif tahun ajaran terkait, dan sandi tetap diperlukan. Mengubah periode login mengakhiri sesi peserta yang ada. JavaScript dan browser modern diperlukan; pengujian fisik printer dan Windows masih diperlukan.

Semua admin dengan sesi sah dapat menyiapkan kartu, termasuk meminta sandi; belum ada peran khusus atau autentikasi ulang per pengungkapan. Sandi tidak disisipkan pada halaman awal, URL, atau audit, tetapi dikirim ke browser admin setelah konfirmasi. Gunakan HTTPS tepercaya dan perangkat aman; proxy tepercaya harus mengganti `X-Forwarded-Host`/`X-Forwarded-Proto` dan tidak merekam body permintaan/respons. PDF, riwayat unduhan, spool/antrean printer, tangkapan layar, dan kertas yang berisi sandi tidak dilindungi oleh aplikasi: batasi akses, distribusikan secara aman, dan hapus sesuai kebijakan sekolah. `no-store` dan pengosongan tampilan tidak dapat menjamin penghapusan seluruh salinan di browser/perangkat. Fitur membutuhkan skema sampai `024`; jangan gunakan data asli sebelum pengujian keamanan dan operasional selesai.

### Login peserta dan jadwal — pratinjau

1. Setelah migrasi `015_participant_password_and_active_period.sql` dan `024_academic_years.sql`, siapkan **tahun ajaran aktif, periode pada tahun itu, roster kelas aktif, identitas dan sandi** di menu admin. Buka **Data Peserta → Periode Ujian** dan pilih **Aktifkan login** untuk satu periode; konfirmasikan dampaknya. Saat migrasi `015` pertama kali diterapkan, periode login awalnya kosong sehingga peserta belum dapat masuk sampai admin mengaktifkannya. Migrasi `016` tidak mengubah pilihan yang sudah ada. Migrasi `024` menonaktifkan login dan mengakhiri sesi saat upgrade sampai periode lama dipetakan dan periode baru diaktifkan manual. Admin juga dapat menonaktifkan login. Periode aktif dipilih manual dan tidak berubah otomatis berdasarkan tanggal mulai/akhir.
2. Pada `/login` pilih **Masuk sebagai peserta**, atau buka `/peserta/login`. Peserta cukup mengisi username dan sandi; server memakai periode yang diaktifkan admin, bukan pilihan atau parameter dari peserta. Username tidak membedakan huruf besar/kecil. Username yang sama pada periode lain adalah identitas terpisah; gunakan sandi untuk periode yang aktif. Sandi lama, termasuk spasi dan karakter lain yang sebelumnya sah, tetap berlaku sampai di-reset. Kelas yang penempatannya berakhir tidak dapat masuk sampai ditempatkan kembali.
3. Setelah masuk, peserta melihat **identitas dan jadwal pelaksanaan yang telah dirilis untuk siswa itu pada periode login aktifnya**. Daftar hanya memuat jadwal yang dimulai hari ini menurut zona **masing-masing pelaksanaan** (WIB/WITA/WIT), termasuk yang belum dimulai atau sudah berakhir hari ini. Pengecualian: jadwal yang mulai **kemarin dan masih berlangsung** juga terlihat; saat berakhir, jadwal itu hilang dari daftar. Tanggal lainnya disembunyikan, termasuk jadwal yang mulai lebih dari satu hari lalu walaupun durasinya panjang. Rancangan, draf, dan jadwal siswa lain tidak ditampilkan. Server menyaring sebelum menghitung dan memaginasi 20 jadwal per halaman; jam database menentukan hari dan status. Dengan JavaScript aktif, **Muat ulang** mengambil data terbaru tanpa memindahkan posisi scroll bila memungkinkan; tanpa JavaScript tautan tetap bekerja melalui navigasi penuh. **Soal, pilihan, kunci jawaban, kode token, dan data peserta lain tidak dikirim** ke halaman jadwal. Nilai hanya dikirim untuk pengerjaan milik peserta yang sudah selesai dan kategorinya sedang dibuka admin; secara default ketiga kategori terbuka.
4. Setiap identitas/periode hanya memiliki **satu sesi peserta aktif**, maksimal 8 jam. Login di browser/perangkat lain menggantikan sesi lama; permintaan berikutnya dengan sesi lama ditolak. **Mengganti atau menonaktifkan periode login mengakhiri semua sesi peserta**, termasuk saat kembali ke periode lama; peserta perlu masuk lagi. Reset sandi, perubahan identitas, atau berakhir/berubahnya penempatan kelas juga membatalkan sesi lama. Keluar menggunakan tombol **Keluar**; jika server gagal mengakhiri sesi, ikuti peringatan dan coba lagi. Sesi peserta dan admin terpisah. Halaman yang sudah terlanjur terlihat di layar/peramban tidak dapat ditarik kembali; keluar dan tutup browser pada perangkat bersama.
5. Setelah **lima percobaan gagal** untuk kombinasi periode dan username, login kombinasi itu dikunci sementara selama **15 menit**. Pesan kegagalan yang sama digunakan untuk username tidak dikenal; keterangan lima percobaan di halaman login selalu ditampilkan dan **bukan** bukti akun tersebut terkunci. Reset sandi tidak otomatis membuka penguncian. Admin dapat membuka penguncian aktif yang dipilih melalui **Akun Peserta** (lihat langkah di bawah), atau menunggu sampai berakhir. Ada batas tambahan **180 percobaan berformat valid per menit secara global** untuk seluruh proses yang berbagi database; bila penuh, semua peserta dapat terdampak hingga jendela berikutnya. Buka kunci peserta tidak mengubah batas global ini. Batas global bukan batas per IP dan dapat disalahgunakan untuk menghambat pengguna lain; audit login lengkap belum ada.
6. Database hanya menyimpan hash token sesi, bukan token mentah; cookie peserta `HttpOnly`, `SameSite=Strict`, terbatas pada `/peserta`, dan `Secure` secara default pada production. Pembatas percobaan menyimpan digest kombinasi periode/username dan waktu, bukan sandi; baris lama dibersihkan secara oportunistik setelah 24 jam saat ada login berikutnya, bukan dijamin tepat waktu. Verifikasi login memakai hash scrypt dan tidak membuka salinan sandi terenkripsi; pembuatan, reset, dan tampilan sandi tetap membutuhkan kunci peserta yang cocok.

#### Buka kunci login peserta

1. Setelah migrasi `016_participant_login_unlock.sql`, buka **Data Peserta → Akun Peserta**, pilih periode akun yang dimaksud, cari peserta berdasarkan nama, NISN, kelas, nomor, atau username, lalu tekan **Muat ulang** untuk status terbaru. Periode daftar ini tidak mengubah periode login aktif.
2. Tombol **Buka kunci login** hanya muncul pada akun dengan penguncian yang masih aktif saat daftar dimuat. Periksa nama, NISN, username, dan periode di dialog, lalu pilih **Ya, buka kunci**. Jika waktu sudah berakhir atau data berubah, tindakan ditolak; muat ulang dan periksa lagi.
3. Pembukaan mengatur ulang kegagalan hanya untuk kombinasi periode/username itu. Sandi, identitas, penempatan, sesi yang sudah ada, periode login, pembatas global, serta kunci akun lain tidak diubah. Lima kegagalan berikutnya tetap dapat mengunci kembali. Pastikan periode login yang benar aktif dan kelas peserta masih aktif; buka kunci sendiri tidak memperbaiki sandi yang salah atau pembatas global yang penuh.
4. Tindakan berhasil dicatat dengan peserta, admin, dan waktu di **Riwayat tindakan akun**; daftar menunjukkan maksimal 20 tindakan sandi/buka kunci terbaru per periode. Tindakan identitas dan upaya yang gagal belum tercatat; catatan bukan audit login menyeluruh dan tidak kebal-ubah oleh pengelola database. Semua admin bersesi sah dapat melakukan tindakan ini; hak khusus belum ada. Pembukaan tidak membutuhkan file kunci sandi, tetapi tidak memulihkan kunci yang hilang atau membuka salinan sandi lama.

Gunakan **data fiktif** dan HTTPS tepercaya. Pembatas ini belum cukup untuk melindungi layanan dari seluruh serangan atau trafik terdistribusi; sebelum penggunaan sebenarnya diperlukan perlindungan jaringan/IP yang dikonfigurasi dengan proxy tepercaya, audit, uji keamanan dan beban pada server/jaringan sasaran, serta penyelesaian modul ujian.

### Kunci dan sandi peserta

**Siapkan kunci sebelum membuat sandi.** Kunci adalah file acak 32 byte yang disimpan **di luar direktori proyek, repository, database, dan backup database**. Jika instalasi sudah pernah memakai sandi peserta atau database memiliki pengikat kunci, **gunakan/pulihkan kunci lama yang cocok; jangan membuat kunci pengganti**. Contoh perintah di bawah hanya untuk database yang telah dipastikan tidak memiliki pengikat maupun sandi. Perintah tersebut memeriksa file, tetapi **tidak memeriksa isi database**. Buat folder yang hanya dapat diakses akun layanan aplikasi dan pengelola server. Contoh Windows PowerShell (sesuaikan lokasi; pastikan folder bukan bagian checkout):

```powershell
New-Item -ItemType Directory -Force -Path 'C:\ProgramData\NusaCBT\keys'
npm run participant:key:create -- 'C:\ProgramData\NusaCBT\keys\participant.key'
```

Perintah tidak mencetak kunci dan **menolak menimpa file yang sudah ada**. Pemeriksaan juga menolak path di dalam direktori aplikasi atau direktori dengan penanda repository `.git`; tetap pastikan lokasi dan cadangannya benar-benar di luar repository dan database. Di sistem Unix file baru dibuat dengan mode `0600`; di Windows atur ACL NTFS folder dan file agar hanya akun layanan dan pengelola berwenang yang dapat membacanya. Periksa izin backup, direktori induk, dan akun layanan secara lokal. Jangan unggah file kunci atau isi file ke Git, chat, log, atau perangkat bersama.

Tambahkan **path**, bukan isi kunci, ke `.env.local`, lalu restart aplikasi. Pada Windows contoh berikut memakai garis miring agar aman untuk file env; sesuaikan dengan lokasi sebenarnya:

```dotenv
NUSACBT_PARTICIPANT_KEY_FILE=C:/ProgramData/NusaCBT/keys/participant.key
```

Cadangkan file kunci secara aman dan **terpisah** dari database, dan uji pemulihannya di lingkungan terisolasi. Gunakan kunci yang sama untuk seluruh proses aplikasi yang memakai database yang sama. Database mengikat kunci pertama saat sandi pertama dibuat; kunci yang berbeda ditolak dan tidak boleh dipakai untuk reset maupun membuat sandi baru. Jika kunci hilang, salinan sandi lama tidak dapat dibuka; pulihkan file kunci yang benar. **Rotasi kunci dan prosedur reset seluruh sandi setelah kehilangan permanen belum tersedia**: jangan menghapus pengikat, mengganti file, atau mengubah tabel secara sembarangan. Simpan backup database dan kunci yang cocok, dengan kontrol akses terpisah.

1. Setelah migrasi sampai `016`, buat penempatan dan identitas siswa. Buka **Data Peserta → Akun Peserta**, lalu pilih periode. Semua admin yang sudah login berwenang dalam tahap ini; peran operator/hak khusus belum ada.
2. **Buat sandi** untuk satu siswa secara otomatis atau manual. Sandi baru maupun reset harus tepat **8 huruf kapital A–Z**, tanpa angka, spasi, atau simbol; sandi manual harus dikonfirmasi. Generator memakai pilihan acak kriptografis dari 26 huruf. Sandi lama tetap dapat digunakan dan ditampilkan dengan kunci lama yang cocok, tanpa reset massal. Hindari sandi manual yang mudah ditebak; ruang sandi delapan huruf lebih kecil daripada sandi otomatis sebelumnya, sehingga pembatas login dan perlindungan jaringan tetap penting.
3. **Buat sandi otomatis** memproses maksimal 25 identitas berkelas aktif yang belum memiliki sandi, menurut urutan nama, terlepas dari pencarian. Ulangi bila ada sisanya. Hashing sengaja mahal sehingga batch memerlukan waktu. Jika data berubah, seluruh batch dibatalkan; sandi yang ada tidak pernah ditimpa.
4. Daftar menyamarkan sandi secara default. Pilih **Lihat sandi → Tampilkan sandi** hanya bila diperlukan. Penampilan berhasil dicatat dengan admin, peserta, dan waktu, tanpa nilai sandi. Tampilan ditutup otomatis setelah 60 detik atau saat halaman tidak aktif. Audit juga mencatat pembuatan, reset, dan buka kunci login yang berhasil; 20 peristiwa terbaru per periode ditampilkan. Perubahan identitas dan upaya yang gagal tidak dicatat, dan tabel audit ini belum kebal perubahan oleh pengelola database.
5. **Reset sandi** mengganti hash dan salinan terenkripsi untuk satu peserta setelah konfirmasi; sandi lama tidak lagi cocok. Bila kelas tidak aktif, sandi tetap tersimpan tetapi tindakan dinonaktifkan sampai siswa ditempatkan kembali. Database tidak otomatis menghapus riwayat audit atau sandi saat kelas berakhir.

Hash scrypt digunakan untuk verifikasi login peserta; salinan terpisah dienkripsi AES-256-GCM dengan kunci tersebut. Sandi tidak dikirim ke halaman daftar awal, URL, atau catatan audit. Sandi manual dikirim ke server saat disimpan dan sandi yang dibuka dikirim ke browser; gunakan HTTPS tepercaya, perangkat admin yang aman, dan konfigurasi proxy yang tidak mencatat isi permintaan/respons. Jangan gunakan data asli sampai keamanan dan operasional diuji. Sesi admin saat ini cukup untuk melihat sandi; belum ada autentikasi ulang khusus untuk setiap penampilan.

Ini **bukan** jaminan kapasitas produksi, uji Windows, atau jaringan LAN sekolah.

## Keamanan dan privasi

- Hash kata sandi admin menggunakan scrypt (N=2^15, r=8, p=3), salah satu konfigurasi [OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html#scrypt); sesi memakai token acak, dengan hash token disimpan di PostgreSQL. Setelah lima kegagalan, akun dikunci selama 15 menit. Ini belum menggantikan pengujian keamanan menyeluruh atau pembatasan trafik berbasis IP.
- Cookie sesi `HttpOnly` dan `SameSite=Strict`; pada production cookie `Secure` aktif secara default dan memerlukan HTTPS yang tepercaya. HTTP hanya untuk uji lokal terisolasi tanpa data asli. Perlindungan HTTPS/proxy untuk LAN sekolah masih harus disiapkan dan diuji.
- Template pada `public/templates` berisi data fiktif dan tetap dapat diunduh tanpa login. Data asli, soal rahasia, password, `.env.local`, kunci, dan backup tidak boleh dimasukkan ke repository publik.
- Hak akses operator terpisah belum diimplementasikan. Semua admin yang memiliki sesi sah dapat mengelola dan melihat sandi peserta; akses sensitif dicatat di database, tetapi log tersebut belum kebal-ubah. File kunci dan cadangannya harus dikelola terpisah sesuai petunjuk di atas.
